# Устройство проекта

## Поток выполнения

`game/index.html` подключает обычные скрипты в заданном порядке. Сборщик JavaScript не используется: те же файлы открываются через `file://`, WKWebView и Electron. Игровые модули экспортируют интерфейсы в `window`; модули логики также доступны через CommonJS для тестов.

`game/game.js` связывает меню, ввод, игровой мир, диалоги, звук, сохранения и цикл отрисовки. `game/engine.js` содержит физику, главы, противников, боссов, предметы и сериализацию мира. Логика обновляется фиксированным шагом; визуальная интерполяция в `presentation.js` сглаживает движение между шагами.

| Задача | Файлы в `game/` |
| --- | --- |
| Главное окно, меню, HUD | `index.html`, `style.css`, `game.js` |
| Игровой мир и механики | `engine.js`, `upgrades.js`, `items.js` |
| Гуров и остальные персонажи | `actor.js`, `cast.js`, `acting.js` |
| Кафедра и индивидуальные жесты | `faculty.js`, `faculty-data.js`, `faculty-motion.js` |
| Фон, эффекты, интерполяция | `environments.js`, `ivan-effects.js`, `presentation.js` |
| Речь во время игры | `ambient-speech.js`, `encounter-speech.js`, `department-speech.js` |
| Диалоги и завершение глав | `story.js`, `course-story.js`, `completion.js` |
| Вступление, массовка и финальный мультфильм | `prologue.js`, `prologue-lines.js`, `crowd.js`, `epilogue.js`, `epilogue-stage.js` |
| Поражение игрока и боссов | `player-death.js`, `defeat.js` |
| Звук, музыка, голосовые банки | `audio.js`, `music.js`, `voices.js` |

Сворачивание окна сохраняет текущий режим сцены и замораживает игровой цикл. `Soundtrack.suspend()` приостанавливает весь `AudioContext`, сохраняя источник реплики, очередь и автоматизацию замедления перед боссом; `resume()` продолжает тот же аудиопоток. Загрузка звука в фоне не возобновляет контекст. Смена реплики, пропуск сцены, выход в меню и выключение звука по-прежнему отменяют речь явно.

## Ресурсы

`game/assets/art-manifest.json` явно связывает игровые переменные с текущими PNG. `tools/prepare_assets.py` превращает их в пять JS-банков с data URI. Это обеспечивает офлайн-загрузку без сервера и дублирования больших картинок в Git. Версии в именах PNG обозначают выбранные игровые ассеты, а не папки со старыми сборками.

`game/assets/voices/manifest.js` связывает пару «персонаж + точный текст» с записью. Остальные файлы в этой папке содержат готовый звук и загружаются по мере надобности. `game/assets/music/` содержит шесть готовых музыкальных банков. `roman-efforts-data.js` хранит короткие звуки действий Романа, `gurov-efforts-data.js` — четыре возгласа Гурова при обычном и двойном прыжке. Они воспроизводятся отдельно от очереди реплик и не приглушают музыку. Эти аудиобанки являются исходными ресурсами релиза и входят в Git: личные записи и модели для запуска не нужны.

В бою с Иваном Равиль использует `RAVIL_BATTLE_LINES` из `engine.js`: пять угроз алгеброй в первой фазе и три ответа на академический отпуск во второй. `ambient-speech.js` резервирует один ответ Равиля между репликами босса и выбирает текст по текущей фазе непосредственно перед воспроизведением. Объявление второй фазы звучит первым; начатая речь сохраняется при заставке. Поражение, поимка, смена уровня и диалог отменяют боевые угрозы. Вне этого боя остаются обычные реплики спутника.

Во второй фазе Иван призывает тёмных Романов: `engine.js` управляет предупреждением, выходом из портала, боем и растворением; `summon-effects.js` рисует портал, круги и частицы. `cast.js` привязывает свечение глаз к очкам в каждой позе. Звуки призыва в `audio.js` используют канал эффектов и не прерывают реплики. При обновлении списка противников интерполяция в `upgrades.js` сопоставляет объекты по идентичности, чтобы исчезновение одного Романа не сдвигало другого. Правила и результаты проверки — в [BOSS-BALANCE.md](BOSS-BALANCE.md).

`tools/release_files.py` определяет состав дистрибутива по подключениям HTML, музыкальным темам и голосовым банкам. PNG для редактирования, тесты и рабочие материалы в приложение не копируются.

`crowd.js` хранит координаты кресел аудитории, перемешивает одежду один раз при создании сцены и рассчитывает выход из рядов к двери. В аудитории 21 студент массовки и отдельное место Ивана. Четыре рисованных цикла бега содержат по восемь фаз; масштаб фиксирован на весь цикл, небольшие копии кадров готовятся при загрузке. Те же анимации используются у студентов во дворе. Исходные листы и запросы генерации перечислены в [PROLOGUE-ART.md](PROLOGUE-ART.md).

## Оболочки и данные игрока

`native/App.swift` открывает локальный HTML в WKWebView; `desktop/main.cjs` — в изолированном окне Electron без Node.js в странице. Оболочки используют тот же игровой код.

Ключи `gurov-last-lemma-v1` и `gurov-last-lemma-victory-v1`, идентификатор `local.gurov.lastlemma` и внутреннее имя Electron сохранены для совместимости прогресса. Они не обязаны совпадать с названием игры. При изменении формата сохранений нужна миграция и проверка старых данных.

## Проверки

`*.test.cjs` проверяют механику и состояния без браузера. Браузерные сценарии проверяют реальные сцены, звук и управление. `fixtures/` содержит последовательности нажатий для обоих улучшений и маршрута кафедры; `campaign-clock.cjs` управляет временем теста. Это входные данные проверок, а не старые отчёты.

Отчёты и скриншоты находятся только в `tests/.output/`. Проверка дистрибутивов сравнивает упакованные файлы с игровым runtime и проверяет контрольные суммы архивов.
