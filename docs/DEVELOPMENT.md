# Разработка и выпуск

## Требования

- Python 3.9+ для подготовки ресурсов и упаковки. Используется стандартная библиотека.
- Node.js 22+ и npm для тестов; Playwright закреплён в `package-lock.json`.
- macOS 12+ и Xcode Command Line Tools для приложения Mac (`xcode-select --install`).
- Для Windows-архива нужен официальный Electron, версия и SHA-256 в `project.json`. Его можно упаковать на Mac или Linux.

Все команды выполняются из корня проекта. В Windows при необходимости замените `python3` на `py -3`.

## Ежедневная работа

```sh
python3 build.py --web-only
```

Откройте `game/index.html`. После правок JavaScript достаточно обновить страницу. После изменения PNG или `art-manifest.json` повторите подготовку ресурсов. Не редактируйте пять сгенерированных банков изображений вручную.

```sh
npm ci
npx playwright install chromium
npm test
npm run check
npm run test:browser
npm run test:campaign
```

В Linux CI перед первым браузерным запуском используется `npx playwright install --with-deps chromium`. Если нужно проверить установленный браузер, задайте переменную `GUROV_BROWSER_EXECUTABLE` с полным путём к его исполняемому файлу. По умолчанию используется Chromium, установленный Playwright. Документация: [браузеры Playwright](https://playwright.dev/docs/browsers).

- `npm test` — проверки логики без браузера.
- `npm run check` — синтаксис JavaScript и покрытие игровых текстов озвучкой.
- `npm run test:browser` — вступление, финал, самонаведение, реплики в бою, предметы кафедры, звуки прыжка без приглушения музыки, возобновление озвучки после сворачивания и сохранение боевой темы после меню паузы.
- `npm run test:campaign` — полное прохождение обеих веток улучшений через игровые нажатия.
- `python3 tools/check_repository.py` — состав будущего репозитория, размеры, ресурсы и локальные пути.

Снимки и отчёты сохраняются в `tests/.output/`. Сценарии не используют сохранения игрока. После нативной сборки на Mac доступен отдельный запуск:

```sh
"dist/Гуров — Последний удовл.app/Contents/MacOS/Gurov" --verify-game
```

Он проверяет WKWebView, управление, звук, продолжение реплики после настоящего сворачивания окна и запись сохранения в отдельном временном хранилище.

## Дистрибутивы

```sh
python3 package_game.py --target browser
python3 package_game.py --target macos
python3 package_game.py --target windows --electron-runtime /path/to/electron.zip
```

`browser` — значение по умолчанию. `all` собирает все три варианта на Mac; ему также нужен Electron. Скрипт не скачивает программы автоматически и проверяет SHA-256 Electron до распаковки. Если runtime отсутствует, команда выводит точную официальную ссылку для закреплённой версии. Альтернативное место кэша — `.build/electron/`.

Архивы и `manifest-<version>.json` с размерами и SHA-256 находятся в `dist/releases/`. Манифест описывает архивы последнего вызова упаковщика. После сборки:

```sh
python3 tests/verify_releases.py
```

Проверка сравнивает каждый игровой файл с исходным runtime, проверяет CRC и SHA-256; для Windows также заголовок PE x64 и включение лицензий Electron. Это не заменяет запуск на Windows. Mac-приложение подписывается локальной ad-hoc подписью, без сертификата издателя и нотариализации.

Название, версия, build number и закреплённый Electron задаются в `project.json`. При изменении версии обновите также `package.json` / `package-lock.json` и `desktop/package.json`; проверка репозитория обнаружит расхождение. Внутренние ключи сохранений не переименовывайте вместе с игрой.

## Изменение аудио

Готовые игровые банки являются частью исходников: обычная сборка не требует TTS, GPU, голосовых записей или доступа к внешнему сервису. При замене озвучки обновляйте банк персонажа и `voices/manifest.js` вместе; `npm run check` проверяет соответствие точным текстам.

`tools/compose_score.py` — исходник музыкальной композиции. Для необязательной повторной генерации установите зависимости из `tools/requirements-music.txt` в отдельное виртуальное окружение и запустите скрипт. Он заменяет шесть музыкальных банков в `game/assets/music/`; WAV и метрики складывает в `.build/music/`. Для простой сборки запускать его не нужно.

## Подготовка к GitHub

В Git входят код, текущие PNG, готовые аудиобанки, маршруты тестов и документация. `.gitignore` исключает сборки, модели, личные записи и отчёты. Исторические материалы вынесены в отдельный локальный архив за пределами проекта; он не требуется для сборки.

GitHub Actions в `.github/workflows/ci.yml` проверяет проект на Linux: подготовка ресурсов, тесты логики, браузерные сцены и обе ветки кампании. Автоматической публикации или загрузки личных файлов нет.

Готовые ZIP размещайте в GitHub Releases. В исходниках большие data URI изображений не хранятся; PNG остаются единственным редактируемым источником. GitHub ограничивает отдельные файлы обычного репозитория 100 MiB и рекомендует выпускать дистрибутивы через Releases: [официальное руководство](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).

Перед публикацией выполните `python3 tools/check_repository.py` и посмотрите `git status --short`. Условия использования ресурсов перечислены в [ASSETS.md](ASSETS.md).
